# Proposal: the autonomous Demo-2 loop (after the slice)

Status: proposal for the user (2026-11-08). Nothing here is built. Author: design researcher agent.
Tags: [decided] already in `docs/decisions.md` or the architecture (cited), [proposed] my recommendation
with the main alternative, [open] needs the user or a measurement.
Citations: D = `docs/decisions.md`, A = `docs/architecture.md`, S8/S10/S11/S12 = `docs/sessions/NN-*.md`.

## 0. What exists today (facts that shape the design)

- Body = one process per goal. `praxion-body --goal G --run-dir D` builds one `BodyDriver`
  (`body/crates/body/src/driver.rs`), calls `Arbiter::command` once in `start_goal`, and `settle()` is terminal:
  it sets `Shared.outcome`, writes `summary.json`, and every later tick returns an empty frame
  (`frame()`: `if settled { ... }`). `main.rs` then lingers 60 ticks and exits.
- The arbiter already has what the port needs: `Arbiter::command()` pushes a `Tier::Command` intent, suspends the
  old one, emits `IntentPushed / IntentState / ReplanNeeded / OwnerChanged{generation}`, bumps the generation once.
  `WakeBrain{cause,detail}` is emitted (reflex running too long, hunger) and only logged. `IntentStack::done`,
  `set_state` exist.
- Event log (`eventlog/src/event.rs`): strictly increasing `seq`, `tick`, `ts_ns`, typed `EventKind`.
  The harness reads `events.jsonl` + `summary.json` after the fact (`BodyRun.events()`, `wait_for_outcome`).
- Facts the body can answer (`facts/src/lib.rs`): `has`, `count`, `near`, `near_entity`, `health`, `food`, `air`,
  `burning`, `is_night`, `time_of_day`, `day_time`; inventory via `Perception::inventory`.
- Primitives (`rules/src/registry.rs`): move_to, mine, place, craft, eat, attack, equip, explore, wait, observe.
  No smelt, no container use. Core skills: wood, planks, sticks, crafting table (+near), wooden/stone pickaxe,
  cobblestone, stone sword. The slice adds `get_furnace`.
- Brain (`brain/praxion_brain`): `Goal{text,item,count}`, `router.route` (Jev), `writer.write`, `admission`,
  `practice` (a fresh server + body per run, referee judges), `Ledger` (per-provider budget, `BudgetExceeded`),
  `Evidence` JSONL. The practice room never touches a live world; it stays as is.
- Harness `start_body` = server + forwarder + body for one seed, ports 25640-25659.

Consequence: the port is not only a protocol. The body must first be able to run goal after goal in one
process. That refactor is step A2 and the biggest risk (section 6).

## 2. Body port v0

Scope rule [proposed]: implement only what the loop uses today. The architecture lists more (take-over
resume rows, remote key, body-restart restore); those stay unbuilt until a consumer exists (principle 2).

### 2.1 Transport and handshake

- [decided] Length-prefixed JSON over loopback TCP, one brain connection (A 5.4 "Transport").
- [proposed] Frame = 4-byte big-endian length + UTF-8 JSON object with a `t` field. Max frame 1 MiB; larger = close.
  Alternative: JSON lines (easier to debug with `nc`); rejected because the decision says length-prefixed.
- [proposed] The **body listens**, the brain connects (`--port 127.0.0.1:P`, P from the harness range). Reason: the
  brain must be restartable without touching the game connection (D, session 2.5 "brain and body are separate
  programs"). A new connection replaces the old one (old one gets `bye{reason:"replaced"}`).
- [decided] Handshake `hello{port_version, caps}`, mismatch refused (A 5.4).

```
body  -> brain  {"t":"hello","port_version":0,"caps":["command","snapshot","pop"],"body":"praxion 0.x (abc123)","run_id":"..."}
brain -> body   {"t":"hello","port_version":0}
```
Version mismatch: body sends `{"t":"bye","reason":"version"}` and closes.

### 2.2 Messages (the complete v0 set)

Every body message carries `seq` (u64). [proposed] `seq` of an `event` message **is** the event log `seq`
(already strictly increasing, already persisted). Non-event body messages (`snapshot`, `dropped`, `pong`)
carry `seq` = last event seq at send time. This gives resync a cheap meaning and needs no second counter.

Body -> brain:

```jsonc
// observation: a filtered view of the event log, same payload as events.jsonl
{"t":"event","seq":812,"tick":4521,"event":{"kind":"owner_changed","generation":7,"owner":"skill:3"}}
// state on demand (connect, resync_request, every wake)
{"t":"snapshot","seq":812,"tick":4521,"generation":7,"owner":"skill:3",
 "stack":[{"intent_id":3,"tier":"command","skill":"get_furnace","args":[],"state":"running"}],
 "facts":{"health":20,"food":18,"air":300,"is_night":false,"day_time":4521,"dimension":"overworld",
          "pos":[12,64,-30],
          "inventory":{"oak_log":3,"cobblestone":8}},
 "stale_ticks":0}
{"t":"dropped","seq":812,"n":37}
{"t":"pong","seq":812,"tick":4521}
{"t":"bye","reason":"version|replaced|shutdown"}
```

Brain -> body:

```jsonc
{"t":"command","id":"c-0007",             // brain-chosen, unique per brain run, echoed everywhere
 "skill":"get_furnace","args":[],
 "tier":"command",                         // v0: only "command"
 "expires_at_tick":4621,                   // [decided] A 5.4; brain = last seen tick + ttl (100 ticks)
 "based_on_generation":7,                  // stale -> rejected
 "condition":"count(furnace) >= 1",        // optional guard text, evaluated by the body (section 4.2)
 "budget_ticks":6000}                      // per-goal limit; body settles failed(budget)
{"t":"pop","id":"c-0008","intent_id":3}    // cancel a running entry, or remove a done/suspended one (A 5.4)
{"t":"resync_request"}
{"t":"ping"}
```

Receipts (command lifecycle). [proposed] A receipt is an **event kind**, not a fourth channel:

```rust
// eventlog EventKind, new
CommandReceipt { command_id: String, state: String, // pending|accepted|rejected|expired|settled
                 intent_id: Option<u64>, generation: Option<u32>,
                 outcome: Option<String>,        // settled: done | failed | cancelled | popped
                 failure_kind: Option<String>,   // typed, e.g. not_found, needs_tool, budget
                 reason: Option<String>,         // rejected: stale_generation|unknown_skill|stack_full|bad_condition
                 condition: Option<String> }     // settled: "true"|"false"|"unknown"
```
Order the brain sees: `pending` (received, queued for the next tick boundary) -> `accepted{intent_id,generation}`
(after `Arbiter::command` returned Ok; the generation is the one it just bumped to) -> `settled`. Or `rejected` /
`expired` straight after `pending`. Because it is an event, it is in `events.jsonl`, so the harness, a replay
and the live brain all see the same line. Alternative: a separate `receipt` message; rejected, a second
sequence space and a second persistence path for no gain.

Event forwarding filter [proposed]: forward only `intent_pushed, intent_state, owner_changed, replan_needed,
wake_brain, command_receipt, skill_frame` with `depth == 1`, `run_started`, `note`. NOT forwarded:
`rule_selected`, `primitive_finished`, `explore_frontier`, receipts-engine events, `ledger` (high rate, no
consumer). The brain reads those from `events.jsonl` post hoc (repair digests already do).

### 2.3 Mapping onto existing body code

| Port concept | Existing thing | Change |
|---|---|---|
| command | `Arbiter::command(interp, body, tick, skill, args)` | none; the driver calls it when it drains the inbox |
| accepted.generation | `CommandAccepted.generation` | copied into `CommandReceipt` |
| generation check | `Arbiter::generation()` | `based_on_generation != generation` -> `rejected(stale_generation)` |
| settled | `Decision::Done/Failed` -> `settle()` | `settle` becomes per goal: writes `CommandReceipt settled`, `stack.done(intent_id)`, `summary.json`; no longer ends the driver |
| preempted | `ReplanNeeded` | the goal is **not** settled; it is suspended and resumes (existing `resume_suspended_command`). The brain sees `intent_state` events |
| wake | `EventKind::WakeBrain` | forwarded as an event; no change |
| intent stack | `IntentStack::entries()` | listed in `snapshot.stack` |
| goal budget | `--max-ticks` (process) | new per-goal `budget_ticks` in the driver, same `failed(budget)` path |

Command expiry: the driver drains the inbox once per tick before `arbiter.tick`; `tick > expires_at_tick` ->
`CommandReceipt expired`, the command never starts [decided].

### 2.4 Generation rules

- [decided] Only the body increments it (arbiter does). [decided] a stale directive is rejected.
- [proposed] v0 check is plain equality on commands. The brain refreshes `based_on_generation` from the newest
  `owner_changed`/`snapshot` before sending and retries once on `stale_generation`. Cost: one retry after a
  reflex. Alternative: no check in v0 (the loop only sends goals when idle). Rejected: the check is ~5 lines and
  exercises the decided rule.
- [open] Whether a settlement `preempted` ever exists: with the current arbiter a preempted skill resumes, so
  `preempted` is a state, not a settlement. Keep it out of `outcome` until take-over exists.

### 2.5 Liveness, resync, back-pressure

- [decided] ping/pong both ways at 1 Hz; any message counts; 3 s silence rule (A 5.4, A 3).
- [proposed] v0 reaction to 3 s silence: log `Note{"brain_silent"}`, keep the **current intent running to its
  end** (skills are autonomous), then idle with reflexes on. The decided "hand-written shelter/retreat skill"
  does not exist yet [open: write it with the user; it is a safety piece]. On reconnect the body sends `hello` +
  `snapshot`.
- [decided] Resync = one `snapshot` at seq S then deltas after S (A 5.4). [proposed] Because v0 observations are
  only events plus a snapshot: the brain sends `resync_request` (or reconnects), the body sends a `snapshot`
  with `seq = S` taken atomically with the facts; events with `seq > S` follow. No replay ring buffer in v0.
- [decided] Bounded queues, `dropped(n)`; overflow discards the buffer and requires a new snapshot (A 5.4).
  [proposed] Implementation: driver -> port thread is a `sync_channel(256)`; the driver uses `try_send` and counts
  failures in an atomic; the port thread then sends `dropped{n}` and a fresh `snapshot`. The driver never blocks
  on the network (50 ms tick budget, E13).
- [proposed] Snapshot data: the driver publishes a small `PortState` (generation, owner, stack, facts) into the
  existing `Arc<Mutex<Shared>>` every 20 ticks (1 s) and on every accept/settle; the port thread reads it. No new
  lock pattern. `pos` and inventory come from the same perception calls the facts use.
- [open] `pos`: coordinates are visible to a player via F3 in singleplayer, but the fair-play stance for the
  briefing is not written down. v0 includes it; the user decides if it stays.

### 2.6 Where it lives and how it is tested

New: `body/crates/port` (`praxion-port`: `wire.rs` serde types, `frame.rs`, `server.rs`, `tests.rs`).
Changed: `eventlog/event.rs` (+`CommandReceipt`), `body/src/driver.rs` (inbox drain, per-goal settle, publish
`PortState`), `body/src/cli.rs` (`--port`; `--goal` optional when `--port` is set), `body/src/main.rs` (no exit
on settle in port mode; exit on `bye shutdown` or process kill), `body/src/summary.rs` (`goals` list: one entry
per settled command; top-level `goal` stays the last one so `harness.wait_for_outcome` keeps working).
`--goal G` becomes "inject `command id=cli`" so there is **one** goal-start path (deletes the special-cased
`start_goal`; principle 2).

Unit (Rust, no server): frame round trip incl. truncated/oversized frames; handshake mismatch; expiry; stale
generation; accepted generation equals `Arbiter::generation`; settle writes the receipt then `stack.done`;
overflow -> `dropped` + snapshot; ping silence -> `brain_silent`. Driver tests reuse the interpreter fixtures.
Unit (Python): `FakeBody` (same wire code, scripted events) so brain tests need no server.
Live (harness): add `start_session(seed, ...)` to `harness/praxion_harness/body.py`: server, forwarder and body
with `--port`, returns `BodySession{port, run_dir, referee, fixture}`. Live cases:
1. `get_wooden_pickaxe` over the port gives the same referee inventory as the CLI smoke test, plus `settled done`.
2. Two commands back to back in one process: proves multi-goal.
3. A command while another runs: the first goes `suspended`, the second is `accepted` with a higher generation;
   when the second settles the first resumes.
4. Kill the brain mid-goal and reconnect: the body kept playing, new `hello` + `snapshot`, `seq` has no gap.
5. Expired command (ttl 0) never starts; stale generation rejected.
6. Reflex mid-goal (zombie via fixture): the brain sees `owner_changed` within 1 s.
7. p99 tick work with the port on vs off (measurement 3).

## 3. The autonomous brain loop

New Python modules in `brain/praxion_brain/`: `port.py` (client), `briefing.py`, `curriculum.py`, `ladder.py`,
`memory.py`, `governor.py`, `loop.py`. `router.py`, `writer.py`, `admission.py`, `ledger.py`, `evidence.py` stay as
they are except where noted.

### 3.1 Process model [proposed]

One thread reads the port into a queue; the loop thread blocks on `queue.get(timeout=1)` and handles wake
events. LLM/Jev calls block the loop thread but **the body keeps playing the running skill** (the point of the
decided architecture). Alternative: asyncio; rejected, no concurrency need besides the reader thread.

### 3.2 Wake causes in v0

[decided] The closed list and the 60 s heartbeat are A 5.7 / S8. The subset with a producer today:

| Cause | Source | Rate limit | Action |
|---|---|---|---|
| `start` | connect + first snapshot | once | recover state (3.6), then idle |
| `goal_settled` | `command_receipt settled` outcome done | none (the loop's rhythm) | verify, record, next goal |
| `goal_failed` | same, outcome failed/budget | none | record failure kind, next goal (3.5) |
| `body_wake` | `wake_brain` event (reflex too long, hunger) | 30 s | v0: record and log only; the body handles it |
| `heartbeat` | 60 s timer | 60 s | take a snapshot, diff briefing facts in **code**; wake only on a relevant change |
| `reconnect` | port reconnect | - | resync, then as `start` |

Not in v0 (no producer): chat, take-over ended, ruleset refusal, new threat (reflexes own it).
"Relevant change" for the heartbeat diff [proposed]: no running intent, health < 10, food < 8, night began,
a tool left the inventory. All code, no model (decided: "a code diff over briefing facts").

### 3.3 The loop

```
state: IDLE | WRITING | PLAYING     (PLAYING: the body owns time; the brain only watches)
IDLE --wake--> briefing = build(snapshot, memory)
   proposal = curriculum.next(briefing)     # LLM, or the ladder fallback if the governor says code-only
   goal     = validate(proposal) or fallback
   route    = router.route(goal, catalog)   # Jev -> play | write | ask
   play  -> send command, PLAYING
   write -> admission.run(goal) (minutes, practice room on separate servers) -> admitted ? send command : record failure
   ask   -> the writer decides (slice behaviour)
PLAYING --settled--> verify condition (3.5) -> memory.append(goal record) -> IDLE
```
During WRITING the live body idles with reflexes on. [open] Whether to give it a harmless filler (a known core
goal such as gathering wood) while the brain writes; the decided rule "no filler that changes the world" (S8)
says no. Keep idle; measure the dead time (measurement 2).

### 3.4 Briefing built from body facts [decided: contract in A 5.7 and S12 "briefing contract"]

`briefing.build(snapshot, memory, ladder, catalog, governor) -> str`, hard cap 1500 tokens (chars/4, the lowest
priority section is cut first). Every remembered line carries `(source, age)`; an unlabelled remembered fact is a
test failure (decided, S12).

```
## Now  [live, tick 4521]
health 20/20, food 18/20, day_time 4521 (day), dimension overworld, pos 12,64,-30
inventory: oak_log 3, cobblestone 8
## Ladder  [computed from inventory now]
done: wood, crafting_table, wooden_pickaxe, stone_pickaxe, furnace   next: coal   (rung 6/12)
## Recent goals  [goals.jsonl]
- have a furnace: done, 41 s ago, skill get_furnace (written, 2 repairs)
- have coal: failed(not_found) x2 -> blocked for 2 h
## Skills  [catalog]  name(params) - doc
## Budget  [ledger] $0.31 last hour, $1.90 of $4.50
```
Stable system prompt + primitive catalog first, briefing last (prompt cache prefix, decided A 5.7).

### 3.5 Picking, routing, writing, verifying, failing

- Pick: section 4. Output is one `GoalProposal`; code validates it (4.2) before anything else happens.
- Route: [decided] `router.route(goal, catalog)` as in the slice (play > 0.7, write if all < 0.3, else ask).
  [proposed] One change: the Jev question uses the proposal's `condition` ("does running skill X make
  `count(furnace) >= 1` true?"), not only `item`; needed once goals are not all `get_<item>`.
- Write: [decided] admission as in the slice, <= 3 repairs per goal, 3 fresh seeds + 1 held-out. A rejected
  admission counts as a failure of the goal (4.4).
- Play: send `command` with `condition` and `budget_ticks`; wait for `settled`.
- Verify [proposed]: the **body** evaluates `condition` on its own facts at settle and puts
  `condition:"true|false|unknown"` in the receipt. `done` with `condition:false` = the skill lied (`skill_wrong`,
  counted against the skill). In harness runs the referee also checks the inventory; a mismatch is a test failure
  and a measurement (5). Alternative: Python evaluates the snapshot; rejected, it duplicates the guard evaluator
  and the two drift.
- Failed play is not retried blindly: record, let the curriculum see it in "Recent goals", pick again.

### 3.6 Recovery after a brain restart [proposed]

Connect -> `hello`, `snapshot`. If `stack` holds a running command intent matching an open record in
`goals.jsonl`, go to PLAYING and wait for its receipt. A running intent without a record: log, let it finish, do
not adopt. Idle: IDLE. Ladder progress is always recomputed from the snapshot, never from the file (decided S10
"recompute from the world").

### 3.7 Cost brake (governor)

Decided: warn above a user threshold per hour (S8); at most 3 repairs per goal; a global call-rate breaker that
degrades to code-only after repeated failures; one hard stop set by the user that pauses autonomous LLM work
while the core keeps running (A 3; D "Safety does not depend on the brain"). S8 says "warn, never cut"; the hard
stop in A 3 is the newer rule.

`governor.py` [proposed]:
- `warn_usd_per_hour` (default 1.00) and `hard_stop_usd` (session total; default = remaining ledger budget), both
  from env. Warnings go to evidence and the terminal (no interface exists yet).
- `allow(call_class, estimate)` is false if: `Ledger.ensure` would raise `BudgetExceeded`, or the hard stop is
  reached, or the breaker is open, or the per-cause rate limit is hit.
- Breaker: 3 consecutive errors/timeouts (any provider) -> open 5 min, then one probe call (half-open).
- Code-only mode: no propose/route/write. The goal is the first unmet ladder rung that an **active skill** already
  covers, else stay idle. The body keeps its current intent; reflexes are unaffected.
- Deadlines per call class [numbers by measurement]: propose 60 s, route 5 s, write 180 s; a timeout is an error
  for the breaker. A Jev error is never read as "no" (existing router rule).
- `Ledger.spent_since(window_s)` (new, reads `ledger.jsonl` timestamps) gives cost per hour. [open] The ledger
  budget is per provider; the user's hard stop is total, so the governor sums providers.

## 4. Minimal free curriculum

### 4.1 Ladder as yardstick [decided: S10, A 6.4]

`ladder.py`: a static ordered list of rungs; each rung = `{id, condition}`, `condition` a guard text over inventory
facts. Computed from the snapshot, never from what the LLM did.

```
wood            count(#logs) >= 1          crafting_table   has(crafting_table)
wooden_pickaxe  has(wooden_pickaxe)         cobblestone      count(cobblestone) >= 8
stone_pickaxe   has(stone_pickaxe)          stone_sword      has(stone_sword)
furnace         has(furnace)                coal             has(coal)
iron_ore        has(raw_iron)               iron_ingot       has(iron_ingot)     # needs smelting
iron_pickaxe    has(iron_pickaxe)           diamond          has(diamond)
```
Rungs through `furnace` are reachable with the existing primitives. `iron_ingot` needs furnace use and no
primitive does that. [open] Add a `use_block`/`smelt` primitive (user decision; body change; effects declaration
and conformance test, A 6.2). Until then the loop stalls at `iron_ingot`; that stall is itself a measurement.
Nether/End rungs have non-inventory conditions: later. The ladder is repo data so the user can argue with it.

### 4.2 Goal proposals and completion conditions [decided: every goal has a computable condition, S10]

[proposed] A condition is a **guard text in the existing rule-list guard syntax**, parsed and evaluated by the
body (`count(furnace) >= 1`, `has(stone_pickaxe) and count(cobblestone) >= 16`). Validate with a new
`praxion-body check-guard "<text>"` that reuses the `praxion-rules` parser (unknown names and type errors are
rejected; evaluation is three-valued, unknown stays unknown). Alternative: a closed Pydantic union in Python
(`Has(item,n)`, ...), quicker to write but a second evaluator that can drift from the body's. Recommend guards:
no new language, the checker exists, the LLM already writes guards in skills.

```python
class GoalProposal(BaseModel):          # structured output (responses.parse)
    text: str                            # "get a furnace"
    condition: str                       # guard text
    rung: str | None                     # ladder rung it serves, or None
    rationale: str                       # <= 200 chars, logged only
```
Code validation (`curriculum.validate`), in order; a failure rejects and logs `proposal_invalid{reason}`:
1. `check-guard` passes. A guard using only registry facts is verifiable; otherwise the goal may run but is stored
   `unverifiable:true` and excluded from success statistics (decided, S10).
2. Items named exist in game data ([open] exact source; `praxion-gamedata` has the registry).
3. Condition is not already true in the snapshot (`already_met`).
4. Not blocked (4.4) and not the same as the last goal.
5. Skill name: for `has(X)` / `count(X) >= n` shapes the convention `get_<X>` applies; other shapes go to the router
   with no name and the writer picks one (small change: `Goal.skill_name` optional).
`Goal` (slice) becomes `Goal{text, condition, item?, count?}`. `practice.passed` keeps using the referee inventory
for goals with `item/count`. Other goals run live but have no referee check in v0 [open].

### 4.3 Proposal call [proposed]

One structured call per pick. System prompt (stable, cached): game rules, primitive catalog, "propose ONE next
goal reachable with the known skills plus at most one new skill; prefer the first unmet rung unless a
prerequisite is missing; never repeat a blocked goal". User message: the briefing. Model: the cheaper writer
model (`gpt-6-luna`), measured; escalate only after 2 invalid proposals. Estimated 2k in / 0.3k out (measure).
Alternative: the ladder spine in code with the LLM only writing skills (the option the user declined in S10);
kept as the code-only fallback and as the equal-compute comparison arm of session 11's learning test.

### 4.4 Failure memory [proposed]

Per goal key (normalized condition): `attempts`, failure kinds, `blocked_until`. Rule: 2 failures block the goal for
2 h; a rejected admission counts as a failure. Voyager style: failed goals and kinds appear in the briefing so
the LLM proposes a prerequisite. Drift log (decided, S10): 5 consecutive goals with no rung progress write
`curriculum_drift` to evidence.

## 5. Minimal memory for the loop

[decided] Smallest memory, JSON Lines per world plus an in-RAM index, the event log is the source of truth, a
briefing with a cap, facts with age and source (A 8, S12 stages A-D). v0 builds only what the loop reads.

`local/worlds/<world_id>/` (machine-local, git-ignored; `world_id` = harness run id now, the save name later):

| File | Writer | Line | Key (last line wins) |
|---|---|---|---|
| `goals.jsonl` | brain | `{goal_id, text, condition, unverifiable, rung, status: open/done/failed/blocked, command_id, intent_id, skill, skill_origin: core/active/written, ticks, failure_kind, condition_result, referee, cost_usd, t_start, t_end}` | `goal_id` |
| `skill_uses.jsonl` | brain | `{skill, goal_id, outcome, failure_kind, ticks, t}` | append only (Wilson input for probation later) |
| `events.jsonl` | body | the existing `runs/<id>/body/events.jsonl` | - |

Reused: `local/brain/ledger.jsonl`, `local/brain/brain.jsonl` (evidence), `local/skills/active/`.
Not built: places/containers (S12 stage B), lessons, vectors, SQLite. Triggers go to `backlog.md`: places when a
goal needs "go back to X" (none before iron); lessons when one `failure_kind` appears in two contexts and a later
repair succeeds (decided, A 6.3), which `skill_uses.jsonl` makes countable now.
`memory.py`: load both files into dicts at start; `append` writes one line and flushes; `recent(n)`, `blocked()`,
`failure_counts(skill)`. The brain writes records only; any statement about the world comes from a snapshot with
its tick. Test: write, kill, reload; a corrupted last line is skipped and logged; the briefing golden file shows ages.

## 6. Risks

1. **Multi-goal driver refactor (A2).** `done`, `started`, `Shared.outcome`, `outcome_delivered`,
   `last_rule_logged`, `Runner`'s `ExploreMemory` all assume one goal per process. Mitigation: one `begin_goal()`
   that resets them; existing CLI smoke tests and the 20-seed first-night set as the regression gate; a review
   round by a different model before merging (AGENTS.md: large or risky change).
2. **Port on the tick path.** Any lock or send in `frame()` risks the 50 ms budget. Mitigation: `try_send`, one
   mutex publish per second, measured (measurement 3).
3. **Briefing-driven bad goals** (unverifiable, unreachable, repeated). Mitigation: validation, failure memory,
   the code fallback; measure the validity rate.
4. **Cost runaway.** Propose roughly every minute over long sessions, plus admission runs. Mitigation: governor;
   one admission at a time.
5. **Co-load** (live server + body + practice-room servers on one PC; A risk 15). Mitigation: admission only while
   the live body is idle; measure tick p99 during admission.
6. **Idle during writing** looks dead and wastes session time. Accepted for v0.
7. **Jev over many skills** (S11 look-alike problem) worsens as the catalog grows; only a handful of skills now.
8. **Stall at `iron_ingot`** (no smelt primitive); see 4.1.
9. **Guard-text conditions** are weak for later goals (no position, no base). Accepted; such goals are
   `unverifiable` until a fact is added to the registry (one place to change).

## 7. Live acceptance (step C) [proposed]

Fresh peaceful seed, 30 minutes wall time, $1.50 hard stop: at least 4 goals proposed, validated, routed and
played; at least one skill written and admitted; the ladder rung count rises; no death; every `done` goal has
`condition:true` and a matching referee inventory; killing the brain once mid-goal and restarting it loses
nothing; setting the hard stop to $0 makes the loop degrade to code-only while the body keeps its running
intent. Evidence: `local/brain/brain.jsonl`, `goals.jsonl`, the run's `events.jsonl`.

## 8. Five measurements to take along the way

1. **Cost per hour of play by call class** (propose, route, write, repair) and **cost per admitted skill**, with
   prompt-cache hit rate. Source: `ledger.jsonl` + `brain.jsonl`. Decides model choice and the warn threshold.
2. **Latency and dead time:** p50/p95/p99 per call class from this PC (decided to measure, S8), and the *goal gap*:
   ticks between `settled` and the next `accepted`, split by plain pick vs pick+admission. Uses event `tick` + `ts_ns`.
3. **Port overhead on the body:** `summary.json` `tick_time.work_p99_ms` and `over_25ms` with the port on vs off on
   the same seeds; events/s forwarded; `dropped` count; reconnect-to-snapshot time.
4. **Curriculum quality:** proposal validity rate by rejection reason, goals/hour, success rate of played goals,
   share `unverifiable`, ladder rungs/hour, `curriculum_drift` count, success of the attempt after a failure-memory
   entry. Feeds the free-vs-spine comparison (S10 open item).
5. **Verification agreement and routing accuracy:** body `condition` vs referee inventory (target 0 mismatches),
   rate of `done` with `condition:false` (skill-lies rate), and Jev route outcomes (`play` that then failed, `write`
   for a goal an existing skill could do) against the final result.
