# Proposal: S3 hands (keyboard and mouse from `ControlFrame`s on macOS)

Status: **proposed**. Author: Claude Fable 5.2, 2026-11-12. Step S3 of
`2026-11-12-macos-real-client-body.md` (accepted). Goal of the step: `move_to` and `mine` run on
the operator's own client; a log is cut; takeover works in the middle of a primitive.

## 1. Shape

```
praxion-body --real-client --hands            praxion-hands (Swift, one process)
  shadow loop (S2)                               owns every OS call:
    driver.frame() -> ControlFrame                 frontmost + cursor-in-window check per post
    translate (pure Rust, unit-tested) ──lines──►  key/button/mouse-move posts, tagged, session tap
    AppliedReport from the client's own   ◄─lines─ listen tap: untagged input -> release all, TAKEOVER
    packets seen on the tee                        stdin closed (body died) -> release all, exit
```

Two processes, one pipe. The body decides, the helper touches the OS.

## 2. Decisions to approve

1. **The helper is the Swift spike grown up, not Rust FFI.** `spikes/macos-hands/main.swift`
   already has the takeover state machine, the listen tap, the focus checks and 289 self-test
   checks, all measured live. It becomes `hands/macos/` (product code) with a line protocol on
   stdin/stdout. Alternative: call CoreGraphics from Rust through `extern "C"`. Rejected for now:
   it needs unsafe CoreFoundation and AppKit code we have not measured, or a new crate, and it
   puts OS input inside the body process. Cost of the helper: one more build step (`swiftc`).
2. **Protocol**, one line per client tick, body to helper:
   `F <tick> <generation> <keys> <dx> <dy> <buttons> <slot>` (keys and buttons as bit masks, dx/dy
   in pixels, slot `-` or 1-9). Helper to body: `READY`, `OK <tick>`, `TAKEOVER <reason>`
   (`foreign_input`, `focus_lost`, `tap_disabled`), `REFUSED <tick> <reason>`. After a takeover the
   helper drops frames until the body sends `ARM`; the body bumps the frame generation and tells
   the driver, so stale frames die (architecture §5.2).
3. **Translation** (Rust, in `praxion-headless`, no OS calls, fully unit-tested):
   - `held`: forward/back/left/right/jump to W/S/A/D/Space. The helper posts only changes.
   - `look`: closed loop. Error = wanted yaw/pitch minus the rotation the client last reported
     minus the deltas already sent but not yet seen; pixels = error / gain; the sub-pixel rest is
     carried. Gain = `(0.6 s + 0.2)^3 * 1.2` degrees per pixel from `mouseSensitivity` s in the
     client's `options.txt` (0.15 at s = 0.5, measured exactly). At most 600 px per tick.
   - `clicks`: Attack holds the left button, Use the right, for as long as frames ask.
   - `select_slot`: one tap of the number key.
   - Not in S3: `menu` (S4), `chat` (stays on the brain side), **sneak and sprint**. Both are
     modifier keys on macOS (Shift, Control); the spike refuses modifiers, and Control plus a left
     click may be read as a right click. A frame that asks for them is applied without them and
     counted (`hands_unsupported`). They get their own spike before they are used.
4. **Receipts come from what the client really sent.** The headless actuator reports the packets
   it planned (`AppliedReport`: dig sequence number, block, face, attacked entity). In real-client
   mode the client plans them; the body reads the client's own serverbound dig, use and attack
   packets from the tee and fills the same report. So a receipt is tied to a packet that exists.
   Risk: the report arrives a tick or two after the frame that caused it; S3 measures whether
   attribution still holds.
5. **Arming in S3 is a flag, not a button.** `--hands` arms once the client is frontmost; after a
   takeover it stays off until the process is restarted. The console button is S5.
6. **Watchdog.** The body is the helper's parent. Helper sees stdin close: release everything and
   exit. Body sees the helper exit: run `praxion-hands --release-all` once and go back to shadow.

## 3. Build order

| Step | What | Passes when |
|---|---|---|
| S3a | Helper: protocol, key diff, buttons, mouse deltas, takeover incl. mouse movement, release on EOF; self-test extended | self-test green; a scripted frame file walks, turns and mines in the fixture; killing the body releases W |
| S3b | Translation + observed `AppliedReport` in Rust, unit tests | tests green; no behaviour change without `--hands` |
| S3c | Live: `move_to` to a point 10 blocks away, then `mine` a log, on the real client | server position within 1 block; the log is in the server inventory; receipts confirmed |
| S3d | Takeover live (needs the operator's hand): move the mouse, press a key, click, mid-primitive | all keys and buttons up within 50 ms; the driver stops; S1's leftover is closed |

## 4. Open

- Look latency: how many ticks between a posted delta and the rotation showing up on the tee.
  The closed loop needs this number; S3a measures it.
- Whether movement primitives tuned on the headless physics (jump timing, edge guard without
  sneak) behave the same when the vanilla client does the physics.
- A second monitor, a non-default key binding, raw mouse input and GUI scale are not handled:
  S3 reads only W/A/S/D/Space/1-9 and `mouseSensitivity`, and refuses to arm if a needed binding
  in `options.txt` is not the default.
